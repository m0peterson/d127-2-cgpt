# d127-2-cgpt

Один тап → два кубика → цитата дня из сборника мемных цитат Стэтхема.

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)](https://app.netlify.com/start/deploy?repository=https://github.com/m0peterson/d127-2-cgpt)

Нажми **Deploy to Netlify**, войди в Netlify и подтверди создание проекта. Настройки сборки уже в `netlify.toml`: `npm run build`, папка `dist`. API-ключи и переменные окружения для этой версии не нужны. Netlify может запросить доступ к GitHub при первом деплое. Если нужен автодеплой именно из этого репозитория, выбери в Netlify **Add new project → Import an existing project** и укажи `m0peterson/d127-2-cgpt`.

## Что работает

- **d127 + d3 одновременно.** d127 выбирает страницу 1–127, d3 выбирает цитату 1–3 на странице. Диапазоны включают обе границы.
- Большая кнопка, короткая анимация, копирование результата и сохранение последнего броска на устройстве.
- Адаптивный интерфейс для мобильных, планшетов и компьютеров; управление клавиатурой и поддержка уменьшенного движения.
- **Генератор, демо.** Поля ключа OpenRouter и модели, редактор примеров, импорт `.txt` и `.json`, демонстрационный результат без сетевых запросов.

Тексты самого сборника не включены: приложение выдаёт координаты для поиска в твоей книге. Новый тап даёт новый случайный бросок, даже в тот же день. Повторы допустимы: кубики независимые, всего 381 комбинация.

Случайность: `crypto.getRandomValues` с отбрасыванием значений, вызывающих смещение при делении по модулю. Финальная пара вычисляется один раз до анимации и показывается одновременно.

## Запустить локально

Нужен Node.js 20+; установка зависимостей не требуется.

```sh
git clone https://github.com/m0peterson/d127-2-cgpt.git
cd d127-2-cgpt
npm run dev
```

Открой `http://localhost:5173`. Для телефона в той же Wi-Fi сети открой адрес компьютера с портом `5173`; HTTPS нужен для копирования в буфер. Сам бросок работает и через локальный HTTP. Не открывай `index.html` через `file://`: приложение использует ES-модули.

```sh
npm test
npm run build
```

`dist/` можно разместить на любом статическом хостинге. Внешние шрифты, CDN и сервер для приложения не нужны. Целевые браузеры: актуальные Safari, Chrome, Firefox и Edge. Работа без JavaScript и в старых браузерах не предусмотрена.

## Примеры для будущей LLM

В редакторе или `.txt`: одна цитата на строку. В `.json`: массив строк.

```json
[
  "Если жизнь закрыла дверь, проверь: возможно, написано «на себя».",
  "Не бойся делать маленькие шаги. Бойся весь день выбирать кроссовки."
]
```

Импорт **заменяет** текущие примеры. Лимиты: 100 примеров, 1000 символов на цитату, файл до 100 000 байт. Пустые строки и дубликаты убираются. Примеры, имя модели и последний бросок сохраняются в `localStorage` только на текущем устройстве. Если браузер запрещает хранилище, приложение продолжает работать в текущей вкладке.

## Как подключить OpenRouter позже

Сейчас это **мок**, а не работающая LLM-интеграция. Демо выбирает один из заранее написанных текстов, не генерирует новый текст по твоим примерам и не использует ключ или модель. Все демо-тексты вымышлены и не приписываются актёру.

В `public/lib/quotes.js` есть:

- `mockProvider`: рабочий демонстрационный адаптер;
- `openRouterProvider`: явная заглушка для реального адаптера;
- `buildMessages(examples)`: готовая сборка сообщений с примерами стиля;
- `parseExamples()` / `normalizeExamples()`: общая проверка импортов.

Контракт адаптера:

```js
const result = await provider.generate({
  apiKey, model, examples, signal
});
// { text: string, source: 'mock' | 'openrouter', model: string }
```

Для следующей версии:

1. Реализовать `openRouterProvider.generate` по актуальной документации OpenRouter: запрос, тайм-аут/отмена, проверка ответа и обработка ошибок ключа, лимита и сети.
2. Заменить `mockProvider` в обработчике формы в `public/app.js`, передать ключ из поля только при явном запросе пользователя. Ключ держать в памяти вкладки; не добавлять в URL, исходники, логи, `localStorage` или GitHub.
3. При прямых запросах из браузера разрешить только нужный endpoint в `connect-src` в `netlify.toml` и проверить CORS. Альтернатива: Netlify Function с проверкой запросов, фиксированным адресом провайдера и ограничением частоты. Общий серверный ключ хранить в переменной окружения функции, никогда в публичной сборке.
4. Сменить подписи «Демо» после подключения и проверить поведение при ошибках и долгих ответах. Серверный прокси, если он используется, не должен журналировать пользовательские ключи.

Поле ключа в текущей версии не читается обработчиком демо, не сохраняется приложением и никуда не отправляется. Политика CSP пока разрешает соединения только с текущим сайтом.
